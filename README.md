# 多门店证照管理系统 LICENSE HUB

为连锁门店登记营业执照、食品经营许可证、消防合格证等证照的**编号、有效期、门店地址、责任人与扫描件**；
总部法务配置各证照类型的提醒提前量；门店负责人上传续证材料并记录受理号；
总部审核通过后，新证才会成为当前有效版本。

零第三方依赖：Python 3.10+ 标准库（SQLite + http.server），SQLite 保存版本链与审核链，扫描件存本地，
提醒在进程内后台线程执行，送达回执由模拟短信适配器返回。

## 一条命令启动

```bash
python3 run.py            # 首次运行自动生成 4 门店 × 3 证照样例；默认 http://localhost:8000
python3 run.py --reset    # 清空样例库重新生成
python3 run.py --port 8080
```

账号（口令均为 `1234`）：

| 账号 | 角色 |
|---|---|
| `legal` | 总部法务（周律）：全量视图、配置提前量、审核裁决 |
| `store1` ~ `store4` | 四家门店负责人：只能管理本店资料、上传续证、登记受理、报失、申请迁址 |

## 交付的功能视图

- **到期看板** `/`：KPI、真正过期清单、30 天内临期（剩余天数 + 待办人）、迁址核查、待审核、待补正、送达回执
- **证照矩阵** `/matrix`：总部视图按**门店行 × 证照列**排列，每格显示编号、有效期、剩余天数、待办人与异常标记
- **续证任务** `/tasks`：提醒引擎按提前量自动生成（临期 / 过期 / 重新核查）
- **材料补正** `/corrections`：受理驳回、审核退回、扫描模糊、原件遗失、衔接空档、迁址核查、过期
- **审核记录** `/audits`：每版本完整审核链（提交 / 通过 / 驳回 / 退回 / 替代 / 系统过期 / 重新核查）
- **提醒配置** `/config`：总部法务按证照类型配置多档提前量（如 `60,30,7`），变更留痕
- **证照详情** `/cert/<id>`：版本链 + 冻结地址快照、扫描件（**保留完整原始比例**）、受理号、补正、审核链、任务
- **门店资料** `/store/<id>`：迁址/经营范围变更（触发全证重新核查）、原件报失

## 业务规则（硬约束）

1. **过期拦截**：不允许提交到期日 ≤ 今天的新证；待审期间证照过期后，总部无法审批通过。
2. **迁址/范围变更**：`address_seq + 1`，该店当前证全部挂「重新核查」补正与任务；
   旧地址序号版本审批时被拦截，**不能沿用旧证**，须按新登记信息重新提交。
3. **版本切换**：同一证照同时只允许一个待审版本；总部通过时旧版自动 `superseded`、新版 `approved`；
   并发审批用 `BEGIN IMMEDIATE` + 状态复读保证**恰好一个成功**。
4. **扫描件模糊**：尺寸不足/低清件自动标记；模糊版本无法审批通过，总部可退回，门店在同版本补传后重新送审。
5. **衔接核查**：新证起始日晚于旧证到期日 → 空档天数补正；早于 → 重叠提醒；次日衔接为正常。
6. **异常标记**：受理驳回、临期未提交（任务挂起）、原件遗失、扫描模糊、新旧证衔接不一致均入补正台账。
7. **数据隔离**：门店账号只能读写本店全部资源（服务层 + HTTP 403 双重校验）；审核、配置仅总部。

## 视觉风格

冷白背景、深灰正文、细线分隔；**朱红（#c63126）只标真正过期、受理驳回、原件遗失、迁址待重新核查**，
临期用琥珀色提示，避免整页警示色。扫描件在详情页按原始宽高比缩放，并可新窗口查看原件。

```bash
python3 -m unittest discover -s tests -v
```

31 个用例，覆盖要求的五类场景：

| 文件 | 覆盖 |
|---|---|
| `tests/test_expiry.py` | 过期拦截（提交/审批两道）、过期标记 + 任务 + 模拟回执、重复 tick 不重复通知 |
| `tests/test_address_change.py` | 迁址触发全证 recheck、旧地址版本审批拦截、按新地址重提后通过、无变化不触发 |
| `tests/test_version_switch.py` | 审核通过旧版 superseded、模糊退回→补传→通过、衔接空档/重叠/无缝、任务结案 |
| `tests/test_concurrent.py` | 8 线程并发审批同一版本仅 1 成功、不同版本互不阻塞、并发提交仅 1 个待审 |
| `tests/test_isolation.py` | 服务层跨店读写拒绝 + HTTP 403/302、越权审批无效、门店不能审核、总部全量可见 |

## 目录结构

```
licensehub/
  db.py          # SQLite schema（版本链/审核链/补正/受理/任务/回执）+ 事务封装
  service.py     # 核心业务规则：权限、提交、受理、补正、审核、矩阵/看板
  scans.py       # 纯标准库 PNG 读写 + 内置 5x7 点阵合成样例件（竖版/横版/模糊）
  notifier.py    # MockSmsAdapter：模拟送达，返回 MOCK- 回执号
  reminders.py   # 进程内提醒引擎（后台线程 tick，可注入时钟）
  seed.py        # 4 门店样例：过期/临期/待审/模糊/驳回/遗失/空档/迁址
  server.py      # http.server 路由、会话 Cookie、multipart 上传、403 隔离
  views.py       # 页面渲染（冷白/深灰，朱红仅标真过期）
run.py           # 单条启动命令
tests/           # 五类场景测试
```

## 说明与取舍

- 时钟可注入（`LicenseService(clock=...)`），测试固定在 2026-10-01；运行时使用真实日期。
- 提醒引擎默认 60 秒扫描一次；每档提前量只通知一次（以 `notifications` 去重）。
- 样例扫描件为程序合成 PNG（内置点阵字库，仅 ASCII 字形），真实使用时直接上传门店扫描 PNG。
- `LICENHUB_FAST_SCAN=1`（测试夹具自动设置）会把合成样例缩小到 1/4 尺寸以加速测试，业务逻辑不变。
